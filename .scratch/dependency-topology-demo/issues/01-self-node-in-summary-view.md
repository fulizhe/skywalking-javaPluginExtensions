# 01 — 总览档左列改为 self 单节点（带总量与端点数）

**What to build:** 改 `agent/demo-app/src/main/resources/static/dashboards/topology.html`，让**总览档**左列只有一个代表本服务的节点；端点维度下沉到明细档与边列表。纯前端，**不碰后端**。

**Blocked by:** 无（可先做）。

**Status:** open

## 为什么要改

既有 spec 自相矛盾：`dependency-topology/spec.md:15` 说「以自身服务为**唯一中心节点**」，L21/L159 说「左列 = 入口端点，零新代码」。实现取了后者 → 总览档左列是一列 `/api/...` 端点名，**汇报图的主角成了接口目录**。本票取前者。

## 页面

- [ ] **summary 档**：左列改建**一个** self 节点（id `s:self`），`name = 本服务`；**明细档左列仍是入口端点、不变**。
- [ ] self 节点 label 两行：`本服务` + `调用 N · 错误 M · 端点 K`。
- [ ] self 节点 tooltip：上述数字 + 窗口内端点清单 + 最慢的那个依赖。
- [ ] 字段全部取自**窗口内已跨桶合并后的边集**（`aggregateEdges` 的输出）：总调用 = Σ`requestCount`、总错误 = Σ`errorCount`、端点数 = distinct `endpoint`。**不新增读口字段**。
- [ ] self 节点坐标**垂直居中**（现状 `rows>1` 时单节点贴顶 `y=60`），`symbolSize` 40。
- [ ] `links[].source` 在 summary 档为 `"s:self"`；`pairSeq` 的 pair 键同步改（否则同一 self → 同一组件的多条边会叠成一条，现状靠 endpoint 区分曲率）。
- [ ] hint / legend / categories 文案分档：`左=本服务（入口端点已聚合）`、`本服务`；明细档维持原文案。
- [ ] 点 self 节点**不跳转**，给明确提示（去边列表看端点明细）；明细档点端点节点跳慢查询页的行为不变。
- [ ] **固定两列坐标保持不变**（左 x=90 / 右 x=620），总览档仍是可截图对比的图。

## 边列表

- [ ] **不动**：仍按「入口端点 × 依赖」逐行、按调用量降序（已决定保留端点明细）。

## 口径说明（硬要求）

- [ ] caveats 新增一条：**总览档左列是入口端点的聚合**，端点维度见明细档与边列表。
- [ ] 同条内点明：**外呼域名不各自成节点**（节点只到组件类型），避免把三个站点误读成三个依赖。

## 不做

- [ ] 不改读口、不改组件名映射、不改插件。
- [ ] 不给 self 节点加下钻（无单一 endpoint 可传）。
- [ ] 不写服务名进 label（读口不给 `service_name`，verify 场景是 `demo-app-verify`）。
- [ ] 不做 JS 单测（无基建）。

## 验证

- [ ] 浏览器实跑目测两档：总览档左 1 右 N、明细档左 N 右 M。
- [ ] 截图取证（总览档固定坐标，可与后续截图对比）。
- [ ] 切换时间窗后 self 节点数字随之变化。
