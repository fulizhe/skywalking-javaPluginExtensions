# 03 — 依赖拓扑读口 + 宿主工具类接入

**What to build:** 新增一个**只读读口**暴露依赖边与依赖节点，并在宿主工具类（桩类 + 拦截器）各加一个方法打通。**左列入口端点不来自本读口**——由现有 Trace 指标读口提供，零改动。

**Blocked by:** 02.

**Status:** resolved —— 读口 `/inner/sw/topology` 已实跑验证（四类调用全部成边）

## 完成情况

全部验收项已落地。实现路径与既有 `SWMetricsUtils` / `MetricsExposeInterceptor` 范式同构（桩类 + 拦截器 + instrumentation define 各一处）。

两点偏离 spec 的补充（均由 issue 01 的取证结论驱动）：

- **多透出了 `spanLayer` 字段**：`componentId=128`（hutool-http）不在组件库里，宿主侧的组件名 fallback 需要它才能给出 `Http(#128)` 而不是空名字。故边除四指标外还带 `spanLayer` + `operations`（明细档标签用）。
- **`fromBucket`/`toBucket` 本期只由前端做客户端过滤**：边只存内存窗口、桶数有界（4 个），持久化之前服务端过滤没有意义。参数已在桩类 javadoc 里标注为"留给持久化阶段"。

组件名三级 fallback：组件库 → `spanLayer(#id)` → `component-<id>`。
