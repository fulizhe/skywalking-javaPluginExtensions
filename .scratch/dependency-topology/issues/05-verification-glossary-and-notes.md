# 05 — 验证回路断言、领域术语与文档

**What to build:** 在既有容器验证回路里为新读口加断言组；补领域术语与开发笔记。**断言只打读口，不测页面渲染。**

**Blocked by:** 02（读口可断言）、04（页面可访问）。

**Status:** ready-for-agent

### 读口断言（主 seam，最高）

扩既有 logfile-reporter 场景的断言脚本，造数后断言：

- [ ] 边列表**非空**，每条边四字段齐全（调用量 / 错误数 / 耗时分位 / 最大耗时）。
- [ ] 某条**已知依赖边**的调用量与错误数**与造数次数一致**。
- [ ] 耗时分位满足序关系 `p50 <= p90 <= p95 <= p99 <= 最大耗时`（**只断序关系，不断具体数值**）。
- [ ] 入口端点列与**现有 Trace 指标读口**在同一时间范围内返回的端点集合**自洽**。
- [ ] **溢出计数**字段存在。
- [ ] **不回归**：现有 Trace 指标读口断言与告警断言**全绿**（证明未改现有聚合与告警路径）。

### 页面可达

- [ ] 断言拓扑页 HTTP 200 且读口含新字段。**不测渲染结果**（本仓验证回路只打读口、从不看页面 HTML，无先例，不新建基建）。
- [ ] 人工目测：两档视图可切换、健康着色与标记可辨、时间窗切换生效、四个口径说明都在页面上、两个方向的跳转都能走通。

### 有界性复核

- [ ] 实跑后复核**真实边数**与**堆占用**，与 issue 02 的内存算术对账；若与估算偏离明显，在笔记里记录实测值。

### 术语与文档

- [ ] 领域词表新增「**依赖边 (dependency edge)**」「**依赖拓扑 (dependency topology)**」「**总览档 / 明细档**」，与「链路分级」「Trace 指标」并列，不退化成同义词。
- [ ] 记录两个取舍及其理由，防止后人误当疏漏而「修掉」：
  - [ ] **为什么只做段内配对**（父段淘汰 → 缺边不可区分）。
  - [ ] **为什么边用小样本池**（边键是交叉积，沿用端点级规模会到数百 MB）。
- [ ] 演示应用的操作避坑笔记补一行：拓扑页入口、依赖面薄的预期。

### 不做

- [ ] 不建 JS 测试基建。
- [ ] 不把断言扩到页面 DOM / 截图比对。
- [ ] 不改既有场景的其他断言。
- [ ] 不实现持久化（另立后续）。

## Comments

> 先例：既有 logfile-reporter 场景断言脚本已按读口断言指标与告警；本票沿用同一形状与断言风格。
> 「不回归」那组断言是本 feature 的安全网——它证明本 feature 确实没碰现有聚合与告警路径，比任何新断言都重要。
