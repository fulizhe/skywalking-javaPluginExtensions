# 02 — 依赖边聚合器：有界内存结构 + 段内配对

**What to build:** 在 Trace 指标聚合器旁新增一块**纯内存有界结构**，做**段内配对**建立依赖边，承载调用量 / 错误数 / 耗时分位 / 最大耗时。**不改现有端点聚合逻辑、不改写路径、不新建任何持久层表、不改载荷结构。**

**Blocked by:** 01（明细档标签口径依赖实跑结论）。

**Status:** ready-for-agent

### 聚合

- [ ] 边键 = `(入口端点, 组件标识, 时间桶)`；在聚合器已收到的链路段对象内做**段内配对**：取该段入口 span 的操作名作左端，遍历该段**出口 span**，取其组件标识作右端，记录该出口 span 的耗时与错误标记。
- [ ] 每条边四字段：调用量、错误数、耗时分位（最近秩，**算法与端点级一致**）、最大耗时。
- [ ] **不设 slow 判定**——慢的根因判定已在端点级由慢规则完成，边不引入第二套阈值口径。
- [ ] **不与告警耦合**——错误判定直接取出口 span 的错误标记，**不改告警分发路径**。
- [ ] **不做跨段配对**（见下方负向测试）。

### 有界（本次主要风险，双维缺一不可）

- [ ] **边数上限** 与 **依赖节点数上限** 两个独立上限；任一触顶时新边并入**兜底边**（与现有端点溢出的 `(other)` 同款处理），并递增**溢出计数**。
- [ ] **耗时分位样本池取小值**（数百量级），远小于端点级样本池。理由：边键是「端点 × 组件」**交叉积**，沿用端点级样本池规模会在边数上限下到数百 MB 量级。
- [ ] **存活桶数固定**，与现有指标晚到窗口一致（当前桶 + 3 个晚到桶）；沿用现有周期性翻转任务淘汰。
- [ ] 存储范式**沿用 Trace 指标聚合器的既有先例**（按分钟桶的键式聚合 + 周期淘汰），不新立范式、不改 ADR-02。

### 单元测试（只测外部行为，不锁内部结构）

- [ ] **段内配对正确**：构造含一个入口 span 与若干出口 span 的段，断言边被正确建立、耗时取自**出口** span。
- [ ] **异步不建边（负向测试，核心取舍）**：构造带父段引用的跨段场景，断言**不产生**跨段边。此测试的目的是**钉住已知边界**，防止后人「顺手修好」而破坏取舍；测试里写明理由（父段可能已被淘汰 → 缺边无法与「没有这个调用」区分）。
- [ ] **无入口 span 的段不建边**。
- [ ] **溢出行为**：超过边数上限后新边进兜底边、溢出计数递增；节点数上限同理。
- [ ] **有界性**：造远超上限的边，断言存活边数不超过上限。

### 不做

- [ ] 不新建 H2 表、不加 TTL、不做 file 模式。
- [ ] 不新增配置开关。
- [ ] 不实现直方图分位（现有指标 v2 单独一条线）。
- [ ] 不捕获对端地址（留模型接口，不实现）。
- [ ] 不改现有端点聚合的任何一行逻辑。

## Comments

> 内存算术（供复核）：`存活桶数 × 边数上限 × 样本池字节`。小样本池下最坏应在**十几 MB 量级**；若沿用端点级样本池规模则是**数百 MB**，在演示应用堆内不可接受——这是本票唯一需要盯紧的数字。
> 先例：现有 Trace 指标聚合器有对应单测，测试基建与命名照它对齐。
