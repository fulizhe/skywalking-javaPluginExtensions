## 0. 一句话

给应用挂一个 SkyWalking Java Agent 插件，就能在**不部署 OAP、不依赖外部后端**的前提下，把全链路与指标留在**应用进程内**：可跨重启（后续 file 模式）回溯、可审计、可聚合，并通过宿主工具类只出**标准化 JSON**，数据与展示彻底解耦。

品牌化叫法：**天枢观测台（Tiānshū · OAPLESS OBSERVABILITY）** —— “北斗第一星，群星所绕之枢轴”。

---

## 1. 为什么做（动机）

- 单体/小团队要“看清自己”，却不想为观测再搭一套 OAP + ES + UI。
- 现有本地缓存（进程内 FIFO）**重启即失、只留最近千条**，故障现场无法复盘、无法审计。
- 目标：把“进程内缓存”升级为**本地可查询的持久层**（对标 Glowroot 的单进程体验），并把 trace 沉淀成**指标**。
- 硬性约束：**监控只能是助力，不是阻碍**——任何采集异常就地吞掉、不阻塞业务线程、不改变对外行为。

## 3. 技术亮点（写博客可展开的点）

1. **H2 内存模式当“全量 trace 持久层”**
   - 单表 `trace_segment`，一条 segment 一行；normal 也入（不再“只收 error/slow”）。
   - 行上限 `shadow_max_rows=100000`（堆 ≈ 80MB）；实测 ≈87k 行时老年代 **124.66MB**。
   - **删除 `trace_level` 列**：错误查 `is_error`、慢查 `latency >= :阈值`（值列查询比“写入时打标”更灵活，顺带规避“写入早于合并”的判定时点问题）。

2. **载荷拆到环形封顶文件（磁盘可预测）**
   - H2 只留 header/索引 + `payload_id` 指针；整段 JSON 经 **GZIP** 写**单个 128MB 环形文件**（写满覆盖最旧，逻辑 id 被覆盖即“过期”）。
   - 借鉴 Glowroot `CappedDatabase` 的**最小形态**（去掉 resize/future/统计）。
   - 磁盘上限 = 小 header + 硬封顶环形，**可预测**。

3. **双源对照 + 逐段 diff**
   - H2 为真相、内存热层（`KeyedLocalStore`，上限 1000 条）为参照；按 `traceSegmentId` 对齐，逐段标 `both / span-diff / h2-only / mem-only`，看得见“口径一致/差异”。

4. **指标口径 = 入口段 a1**
   - 在采集流 `consume` 上**逐段**聚合：段内含 Entry span 即一次事务，normal 天然计入、异步子段天然排除；不阻塞业务线程。
   - 多分辨率：分钟桶翻转落库，整点 rollup 小时表；每桶另有**全局行 `"*"`**。
   - **QPS = 活跃平均**：`总请求 /（有数据桶数 × 桶秒）`，忽略空闲窗口（否则 24h 区间平均会被空闲稀释到 <1）。

5. **慢判定“三处同源”**
   - 告警（`TraceEvaluator`）、H2 明细慢查询（`latency` 阈值）、指标慢判定，**同一套 `slow_rules` + 默认阈值**；指标侧用**只读阈值解析器**（不触发规则命中计数、不改告警行为）。

6. **孤段过滤**
   - 无 Entry 且无 ref 的段（HikariCP/gRPC/后台线程自建）**不入库**，不白占 traceId/行数；计数与来源（`orphanSegments`/`orphanKinds`）在对账口可见。

7. **数据与展示彻底解耦**
   - Agent 只出标准化 `Map`；演示页全部轮询同一批 JSON 契约，可替换为任意消费者。

8. **工程化**
   - 构建：JDK17 工具链 + `release 8` 字节码基线；H2 依赖 shade 重命名隔离。
   - 验证：一条命令端到端（含对账零差异、环形文件定长、指标口径自洽等断言）。

## 4. 实测数据（可引用）

- **容量校准**：`S ≈ 662 B/段`（gzip 载荷）、`K ≈ 1`、`R ≈ 804 B/行`；`N=10万` 行 ≈ 80MB 堆；`F=128MB` 可容纳 ~20 万段（F 有余量）。
- **≈87k 行实测**：老年代 **124.66MB**；H2 插件对象浅和 **30.2MB**（含引用字符串估 ~50MB）；`KeyedLocalStore`（1000 条）估 15–25MB；其余 ~50MB 为 JVM/meter/profile/metrics 缓存与框架。
- **QPS**：活跃平均口径下，`GET:/hello`（1 分钟桶）`80/(1×60)=1.33/s`；压测期全局可达数十/秒。
- `payload_id` 为环形文件逻辑字节偏移，溢出需 ≈9.2 EB（≈1.4×10^16 段，数万年），**无实际风险**。

数据出处：`docs/notes/2026-09-27-h2-mem-capacity-estimate.md`（§7.1/§7.3/§8）。

## 5. 架构与关键决策（ADR）

| ADR | 决策 |
| --- | --- |
| ADR-01 | JDK17 构建工具链 + `release 8` 字节码基线；验证回路 |
| ADR-02 | 有界本地存储**两种形态**：追加式（环形队列，供 JVM/meter/log/profile）与键式（`KeyedLocalStore`，供 trace），接口不强行统一 |
| ADR-03 | trace 明细**载荷拆为 H2 header/指针 + 环形封顶文件**（磁盘硬上限） |
| ADR-04 | H2 mem 作**全量 trace 持久层**（含 normal），`KeyedLocalStore` 降为参照；删 `trace_level` |

## 8. 对比与差异化（博客“我有你没有”）

| 维度 | 天枢（本方案） | SkyWalking | Glowroot | CAT |
| --- | --- | --- | --- | --- |
| 部署依赖 | **零后端 / OAP-less** | OAP + 存储 + UI | 单进程 | 服务端 + 客户端 |
