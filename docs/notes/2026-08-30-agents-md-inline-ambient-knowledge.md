# 2026-08-30: AGENTS.md 下沉经验——环境性知识该内联，条件性知识才走 index

> 范围：仓库文档结构（AGENTS.md + docs/）。状态：已落地。

## 背景

把 AGENTS.md 精简为"每类主题一行触发词 + 指向目录 index.md"时，最初把 **Windows/pwsh 执行环境**也下沉到了 `docs/repo/execution-environment.md`。随后复盘发现这是分类错误，已放回 AGENTS.md 顶部独立一节内联。

## 核心经验：条件性知识 vs 环境性知识

| 维度 | 条件性知识 | 环境性知识 |
|---|---|---|
| 例子 | 模块状态、已知 TODO、ADR | 执行环境、shell 约定、编码约定 |
| 触发时机 | 特定任务阶段（动模块前、规划验证前） | **每条命令、每个会话** |
| 触发器命中率 | 低（特定才读） | 100%（等于没有触发器） |
| 放哪 | 下沉到 docs/ 叶子，AGENTS 留一行触发词 | 内联 AGENTS.md，首屏可见 |

**判别方法**：这个约定是否适用于本仓库几乎每一次操作（跑命令、写脚本、做验证）？是 → 环境性知识，内联 AGENTS.md；否 → 条件性知识，走 index。

## 为什么环境性知识不能下沉

1. **触发器自我引用陷阱**：pwsh 的触发词是"跑脚本时"，但正是不跑 pwsh 的人（默认 5.1 shell）才最需要读到它——他们不知道有这个约定，自然不会去查 docs/。
2. **失败是静默的**：GBK 乱码不是报错，是"看起来正常的乱码"。Agent 会误判为脚本 bug 而开始错误排查，根本想不到去翻文档。静默失败比显式报错贵得多。
3. **成本不对称**：内联成本 ≈ 每次会话多读几行（token 可忽略）；不内联的代价是一次乱码误判 = 数百 token 的错误排查 + 可能动错代码。

## 决策

- pwsh 执行环境约定内联到 `AGENTS.md` 顶部 `## Execution environment (Windows)` 一节。
- 删除 `docs/repo/execution-environment.md`（内容已内联，避免孤儿冗余）。
- 其余主题（模块状态 / TODO / ADR / agents / review / spec）维持 index 模型不动。
