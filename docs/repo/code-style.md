# 代码风格 & 重构规范（code-style & refactor conventions）

何时读：写新 Java 代码、改既有代码、拆分大方法、**纯重构**、对齐代码风格时。
由 `AGENTS.md` → `docs/repo/index.md` → 本文件引用，非始终加载。

## 三个词（leading words）

- **纯重构** —— 只动结构，不动行为。这次"改代码"是重排，不是重写。
- **典型目标** —— 需求里钉住"拆成什么样"的标杆方法（如 `storeLog` 里的数据库操作）。先照它定出该文件的拆分样板，再套用到其余大方法。
- **行为等价** —— 纯重构的完成判据：同一输入下，字段值、异常路径、限速日志、返回契约与重构前一一相等。

## 拆分准则（怎么写才"小"）

- 一个方法一个动作：聚合 / 计算、DB 操作、行映射、构造函数初始化各归各。
- 中间结果用私有小值对象传递（如 `SegmentMetrics`），不新增外部依赖。
- 复用的代码段（如排空循环）抽成私有方法，消除重复。
- 跟随文件既有风格：旧式 Java、显式泛型、既有缩进习惯；注释随代码移动，不新增解释性注释。
- 边界只动本次目标方法与它的直接拆分产物，不动无关代码和无关文件。

## 行为等价清单（改完逐项对照）

以下与重构前一致才算**纯重构**，否则回到重写语义：

- 同步块范围与线程模型
- 全部异常就地捕获 + 计数 / 限速日志（含 operation 名称）
- 水位清理阈值与触发条件
- payload 缺失 / 过期语义与返回 Map 的 key 名
- public / 包级方法签名与返回契约
- 默认值归一化（如 `shadowMaxRows <= 0` 的行为）

## 完成判据（checkable + exhaustive）

1. 模块内 `mvn compile` 编译通过
2. 模块内 `mvn test` 全绿（含被改类的测试）
3. 行为等价清单逐项为"一致"
4. `git diff` 只含目标文件与其拆分产物

## 向 agent 下需求（人类侧模板）

> 按 `docs/repo/code-style.md` 的**纯重构**规范重构 X，**典型目标**是 Y 里的数据库操作。

订阅式补充（任选，加一条改动就更有界）：

- 拆分点清单：聚合 / DB 操作 / 行映射 / 构造函数
- 风格约束：跟随相邻代码 / 不加注释 / 不用新语法特性
- 验收范围：只跑某模块的 `mvn test`
