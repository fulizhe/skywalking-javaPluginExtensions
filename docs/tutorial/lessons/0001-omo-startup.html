OMO 起步：基本流程与常用命令

目标：你学完后，能自己在这个 skywalking 项目里让 OMO 帮你干活，并且知道常用命令怎么敲。

你用的是桌面 GUI（opencode apps）。 GUI 和终端版共用同一套机制，所以下面讲的 agent 切换、@、/、! 在 GUI 里全部一样用——只是你主要用鼠标点击而非键盘快捷键。本课的「agent 下拉」就是 GUI 左下角那个（Sisyphus - Ultraworker / Atlas / Build / Plan）。

先记住一句话：OMO 把 OpenCode 从「一个助手」变成「一支队伍」。 你只管发指令，它负责分派、并行、验收。你不需要背模型名，只需要记住「三种用法」。

一、三种用法（这是全部心法）

OMO 的一切用法都归结为三条路。根据任务复杂度挑一条：

复杂度你做什么适合场景
简单 在 Build 上直接打字 改错字、单文件、简单提问。占日常 90%。
复杂但你想偷懒 切到 Sisyphus - Ultraworker 直接打字 任务大，但你懒得一步一步解释，让它自己探索+干活。
复杂且要精准 在 Plan 上规划 → 再让 Atlas - Plan Executor 执行 多步骤硬活，想先被工程师式追问、出方案再动手。
你的真实 agent 下拉只有 4 项：Build、Plan、Sisyphus - Ultraworker、Atlas - Plan Executor。 下面的用法都是在这 4 个之间切换，不需要记命令名——直接在左下角 agent 下拉里选就行。

用法一：直接打字（在 Build）

默认就是 Build，什么都不加，正常打字就行：

帮我看看 HelloController 里的 NPE 风险

这是最常用的路。你项目里 Build 就是 matt-skills 的主体工作流 agent。

用法二：ultrawork（切到 Sisyphus - Ultraworker）

左下角 agent 下拉选 Sisyphus - Ultraworker，然后正常打字：

给这个项目加一个 JWT 鉴权，遵循现有规范

它会自动：探索代码库 → 并行派 explore/librarian 去查 → 实现 → 校验 → 持续干到完成。你选中的这个 agent 本身就是"ultrawork 模式"，所以不用再打 ultrawork 这词——选中即全自动。

注意：你也可以在 Build 上打字时用 ultrawork 任务 关键词临时切入全自动模式。两种方式都行。

用法三：精准编排（Plan 规划 → Atlas - Plan Executor 执行）

多步骤硬活，想要「先被审，再动手」：

  1. 切到 Plan（matt-skills 的规划 agent，也映射 OMO 的 prometheus）——描述需求 → 它追问、定范围、写方案到 .omo/plans/xxx.md
  2. 切到 Atlas - Plan Executor（或输入 /ulw-execute）→ Atlas 读方案、分派任务、独立校验

好处：中途停止，/ulw-execute 会从断点接续，不会白干。

二、常用命令（背熟这 5 类就够）

① 界面内斜杠命令

命令干嘛的
/new开新会话（相当于清空重来）
/sessions列出、切换以前的会话
/compact压缩会话，省 token（对话太长时用）
/agent切 agent（Sisyphus / Prometheus / Atlas…）
/undo / /redo撤销 / 重做上一条
/exit退出

② 三个必会的小技巧（`@` 不只是引用文件！）

在输入框打 @，会弹出一个带图标的列表——里面其实有三类东西，别以为都是文件：

类别长啥样作用例子
① 文件 显示文件路径 把文件内容加进对话，让它看 看看 @pom.xml 的依赖
② Agent（子 agent 提及） 带图标 + agent 名，如 @explore @oracle @librarian @general、@Metis - Plan Consultant 等 召唤一个专门 agent 去干活（它另开子会话，干完把结果带回） @explore 扫一下 logfile 核心类
@oracle 这个 NPE 怎么规避
③ MCP 工具/资源 如 @tools_list 指示 agent 查看某个外部工具可用清单 （用 MCP 时才会看到，新手先不管）
一句话记住：@文件名 = 让它看文件；@agent名 = 叫一个专门 agent 去干活。前者是你"给它看"，后者是你"派活给分身"。
写法作用例子
@agent名召唤子 agent（explore/oracle/librarian…）@oracle 帮我想想这个架构
!命令直接跑 shell!git status

③ OMO 专属命令

命令干嘛的
/agent打开 agent 切换菜单——比记命令更省事，你的 4 个 agent 都在里面选
/ulw-execute执行 Plan / Prometheus 写好的方案（往往配 Atlas 用）
ultrawork 任务 / ulw 任务在 Build 上临时切入全自动模式（也可直接切到 Sisyphus agent）
/hyperplan对抗式多 agent 规划（互相挑刺）——进阶才用

三、谁在帮你干活（核心 Agent）

Agent一句话角色
Sisyphus总调度，默认主控，拆解+分派
Prometheus动手前访谈你、出方案
Atlas执行方案、派活、验收
Oracle只读高智商顾问：架构/疑难 debug
Librarian查文档、开源代码
Explore快速扫代码库
Metis动手前挑毛病、找遗漏
Momus无情评审方案/代码

你不直接选这些 agent——是 OMO 在后台按任务类型自动分派。你主观上只需要决定「用哪种用法」。

四、你的真实配置（重要！）

这是你这个项目 `.omo/omo.jsonc` 实际状态，跟外面教程不一样，务必记住：

  • sisyphus_agent.disabled: true — Sisyphus 不自动接管主控，主导权留给 matt-skills 的 build/plan。想要 OMO 全托管，得手动敲 ultrawork 或切到 sisyphus agent。
  • goal.enabled: false — goal 钩子已关（就是这个钩子上次拦了你的长消息）。改配置后要重启 opencode 才生效。
  • 只有 opencode-go 一家 provider — 所以 agent 和 category 都绑死在 opencode-go/* 上。

五、上次「发送命令失败」是怎么回事（学到就值了）

你遇到的「Unexpected server error / 发送命令失败」根本不在你的代码里。

真实原因：OMO 的 goal 钩子会在每一条消息上取你的文本当成「目标」去存，而目标有 2000 字符上限。你的长消息（比如带一大段说明的 /teach）超过上限，它抛 InvalidObjectiveError，把整条消息打了回来。

所以以后看到「发送命令失败」，第一反应是：去翻日志，而不是怀疑自己的代码。

C:\Users\lqzkc\.local\share\opencode\log\opencode.log

搜 ERROR 或 InvalidObjective，答案十有八九就在那。

本次已经通过关掉 goal.enabled 根治——这也是你这套配置里它为什么是 false 的原因。

现在练一下（检索练习，别偷看答案）

先在心里答，再点开对答案。

① 想「一键全自动」完成一个复杂任务，最简单敲什么？
ultrawork 你的任务描述（或 ulw 任务描述）。它会自动探索+干活。
② 想在对话里跑一条 shell 命令，消息开头怎么打？
以 ! 开头，如 !git status。结果会直接进入对话。
③ 对话太长、想省 token，用哪个命令？
/compact（压缩当前会话）。注意它只是压缩，不是删除。
④ 看到「发送命令失败 / Unexpected server error」，第一件事该做什么？
翻日志：C:\Users\lqzkc\.local\share\opencode\log\opencode.log，搜 ERROR。多半是工具/配置问题，不是你的代码 bug。
