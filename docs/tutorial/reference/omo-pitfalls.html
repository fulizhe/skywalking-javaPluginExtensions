OMO 避坑手册

走过的弯路都是资产。下次遇到同款症状，先来这里对号入座，别再绕一圈。

这页最值钱。 每一条都是我们真实踩过/纠正过的坑。教训比教程更有用——遇到「怪问题」，先翻这页，再看课程。
先看通用排查清单（底部）。 我们这程总结出一条 5 步法：看日志 → 查本机源码 → 核对真实配置 → 分清内置/MCP → 改了要重启。绝大多数怪问题都能用它兜住。

🕳 坑 1：发长消息报「发送命令失败 / Unexpected server error」

  • 症状：敲 /teach + 一大段说明，弹 toast「发送命令失败 / Unexpected server error. Check server logs for details.」
  • 真相：不是你的代码 bug，也不是网络。OMO 的 goal 钩子在每一条消息上抓文本去存"目标"，而目标有 2000 字符上限（validateObjective 里 MAX_OBJECTIVE_LENGTH=2000）。超了就抛错，整条消息被打回。
  • 我绕过的弯路：一开始我以为是项目代码问题，去 skywalking 插件里找——全错，那串消息根本不在代码里。应该第一时间看 opencode 日志。
  • 正确姿势：翻 C:\Users\lqzkc\.local\share\opencode\log\opencode.log 搜 ERROR / InvalidObjective。
  • 根治：.omo/omo.jsonc 里 goal.enabled 改成 false（已提交，本地 commit 1e36e60）。改完需重启 opencode 才生效。

🕳 坑 2：教学犯了「照通用教程讲」而不是「照你的环境讲」

  • 症状：我在第 1 课讲了「三种用法：切 Prometheus / ultrawork 命令」，你说没有这些。
  • 真相：通用教程里的 agent 名（Prometheus/Hephaestus）≠ 你界面上真实的 agent 名。你的 agent 下拉只有 4 项：Build、Plan、Sisyphus - Ultraworker、Atlas - Plan Executor。其中 Prometheus 在你界面里就叫 Plan，Hephaestus 被禁用（无 OpenAI 凭据），ultrawork 模式靠切到 Sisyphus agent 而不是打命令。
  • 教训：教工具时，必须先看对方当前的真实配置，不要拿官方通用文档糊弄——尤其 agent 名、插件名会因版本/配置不同而不同。（我改过多次，查证靠本机 dist/index.js + .omo/omo.jsonc，别靠记忆。）

🕳 坑 3：以为 @ 只能引用文件

  • 症状：你 @ 弹出大量带图标的 @explore/@oracle/@Metis…，我第一课只讲了「@文件名 引用文件」，你自然懵。
  • 真相：@ 菜单里有三类：
    ① 文件（@pom.xml）→ 让它看文件
    ② 子 agent 提及（@explore/@oracle/@librarian/@Metis…）→ 派活给分身，它另开子会话
    ③ MCP 资源（@tools_list）→ 查看某个 MCP 服务器的工具清单
  • 一句话：@文件名=让它看；@agent名=派活给分身。

🕳 坑 4：@tools_list 以为是「全局工具列表」

  • 症状：你 @tools_list 想「看所有工具」，结果只看到 exa 的搜索工具列表。
  • 真相：@tools_list 是 exa 这一个 MCP 服务器的工具清单（exa://tools/list），不是全局汇总。
  • 两类工具别混淆：
    内置工具 = opencode 自带（bash/read/edit/grep/glob/webfetch…），agent 自动用，不需要 @。
    MCP 资源 = 外部服务器插入的（exa://...、@tools_list），@ 它才暴露。
  • 还有：exa 目前只有基础 web_search_exa 是 enabled:true，高级版（web_search_advanced_exa、web_fetch_exa 等）全被禁用——多半因为没配 API key。日常查资料基础版够用。

🕳 坑 5：控制台里中文显示成乱码（不是文件坏了！）

  • 症状：Get-Content 读 markdown、git diff 看中文，全变 �? 或 ���。
  • 真相：文件本身是干净的 UTF-8 字节（我用 GB18030/UTF-8 逐字节验证过，中文〈插件安装/配置经验〉都在）。乱码只是 PowerShell 控制台用 GBK 渲染 UTF-8 的显示假象。不是 mojibake，千万别去「修」文件。
  • 正确姿势：用 pwsh（PowerShell 7）跑（你环境已配 shell: pwsh），它 UTF-8 端到端不糊。判断乱码真假，用字节层面验证（System.Text.Encoding.UTF8.GetString + 正则匹配中文），别只看终端显示。

🕳 坑 6（你没踩，但要知道）：配置改了不重启不生效

  • 改 .omo/omo.jsonc（如 goal）后，必须重启 opencode（或新开会话）才装配到运行时的 OMO 插件里。当前会话还带旧配置。
  • 我们当时改完 goal.enabled=false 没立刻验证，就是这个原因——不至于错，但要知道「改了≠马上生效」。

✅ 通用检查清单（下次遇到怪问题先走这几步）

  1. 先看日志：C:\Users\lqzkc\.local\share\opencode\log\opencode.log，搜 ERROR/InvalidObjective/Unexpected。十有八九答案就在那，别去翻你的代码。
  2. 查本机源码（比文档准）：C:\Users\lqzkc\.cache\opencode\packages\oh-my-openagent@latest\...\dist\index.js，搜关键字。
  3. 核对真实配置：D:\gitRepository\skywalking-javaPluginExtensions\.omo\omo.jsonc + opencode.json —— 你的 agent 名、禁用项、模型绑定都以这里为准。
  4. 分清「内置」vs「MCP」：内置工具 agent 会自动用；MCP 资源才需要 @。
  5. 配置改了要重启才生效。
