## ✅ 建议做

### #1 演示模式（Presenter Mode）—— 已落地（2026-10-01）

**落地形态**（实现细节见 `agent/demo-app/README.md` 的「演示模式」一节）：

| 原计划 | 实际落地 |
| --- | --- |
| 工具栏开关 + `body` class | 共用外壳 `static/dashboards/presenter.{js,css}`，三页右下角一个开关；模式存 localStorage，跨页保持，也支持 URL `?presenter=1` |
| 折叠 caveats / 隐藏控件 / 图例常驻 / 字号放大 | 全部挂在 `body.pz-on` 下（**未开启时页面与改动前完全一致**）；caveats 收成一行、悬停展开；图例本就常驻 |
| 顶部结论卡（自动算） | 拓扑 = 依赖类型 / 累计调用 / 累计错误率 / 最慢依赖；告警 = 事件数 / SLOW / ERROR / webhook 投递；**指标页不另加卡** —— 它的 KPI 行就是那个结论，只放大 |
| 上一页 / 下一页穿三页 | `‹` `›` 按钮 + `←` `→` 键，`P` 切模式；顺序 指标大屏 → 依赖拓扑 → 告警面板 |

**完成判据核对**：三页在全屏下无运维控件、口径可按需展开、结论数字与 `/inner/sw/*` 逐项一致
（页内自洽校验：`73/1332 = 5.48%`；两种口径本就该不同 —— 窗口边合计 ≠ 进程累计，页面已标注）。

**一处偏离原计划**：原写「指标大屏加结论卡」，实现时改为**放大既有 KPI 行** —— 避免同一组数字在
一页里出现两份计算路径（那正是"图上 3 个依赖、读口 5 个"这类不一致的来源）。

### #2 依赖清单视角（「谁在调我」）—— 已落地（2026-10-01）

**落地形态**：拓扑页第三个视图档 **「清单」**（`topology.html` → 视图 → 清单）。
一行一个外部依赖，**恒为进程累计口径**、不跟时间窗走；该档下关系图收起、表格占满宽度。

| 原计划 | 实际落地 |
| --- | --- |
| 拓扑页加一个「依赖清单」档 | 视图第三档。**不并排展示图** —— 累计表的数字和窗口边的图并排会被读成同一件事，那正是页内 caveats 劝阻的混读 |
| 一张表：组件 / 层 / 累计调用 / 累计错误 / 首次出现 / 最近出现 / 出口操作名 | 全部落地，另加**错误率**（驱动 SLA 色点、也是汇报要问的那句"哪个依赖最不稳定"）与**操作数**（可排序） |
| 可按累计调用排序 | **点列头排序**（组件/层/调用/错误/错误率/首见/最近/操作数），默认累计调用降序。数值相等时按组件名兜底，避免每次刷新行序乱跳 |
| 支持点击回到总览档 | 点行回总览；顶栏档位标签在清单档写死「清单 · 自启动以来」 |
| **成本几乎为零** | 确认成立：**没有新增读口、没有新增存储、没有碰插件** —— 读口早就在无条件附带 `dependencies`（插件侧 `EdgeLifetimeRow`），只差一个视图 |

**「首次出现」怎么区分"一直都有"与"压测才开始碰"**：绝对时刻后加**距进程启动多久**
（`起点` / `+5m` / `+16h40m`，基准是读口的 `lifetimeSinceMs`）。压测前就存在的依赖落在 `起点`，
压测才碰到的会显示明确的 `+Nm` —— 汇报里那句话因此有据可依，而不是靠嘴说。

**完成判据核对**：行数 = 读口 `dependencies` 长度（不分页不过滤 —— 这页要能当"清单"用，
缺行比多列严重得多）；排序与相对时间逻辑已用真实形状的依赖数据跑过断言（全通过）。
组件数硬上限 512，超出计入 `counters.lifetimeDropped`，非 0 时表头提示、不静默隐藏。

**一处主动收窄**：没把「最大耗时」加进表。累计表不存耗时样本（只有 `maxLatency` 单值），
放进一张"谁在调我"的清单里容易被当成"这个依赖的耗时水位"读 —— 那需要 #4 的落库才答得准。
现状：最慢依赖在 Presenter 结论卡里，那里的口径标注已写明。

### #3 慢调用 TopN 榜 —— 已落地（2026-10-01）

**落地形态**：**独立一页** `slow-topn.html`（指标大屏的 Endpoint 指标卡右上角有「慢调用 TopN 榜 ›」跳转）。
一页只发一个请求：`/inner/sw/metrics/query?aggregate=true`。已进演示动线（指标 → **慢调用榜** → 拓扑 → 告警）。

| 原计划 | 实际落地 |
| --- | --- |
| 只做排序 + 版式 + 前 N | 确实只做了这些：7 种排序依据（P95 / 最差 P95 / P99 / 平均 / 慢率 / 错误率 / 请求数）+ 前 N（10/20/50）+ 点列头式版式 |
| "哪个端点慢、慢到什么量级" | 量级给全：请求数 / 错误率 / 慢率 / P50 / P95 / **最差 P95**。加「最差 P95」是因为加权平均会把尖峰抹平，而汇报要问的是"最坏时有多坏" |
| 同一端点在不同时间窗的排名变化能被看出来 | `▲n` / `▼n` / `—` / `新`，**与上一次换档时的名次比**，hint 写明比的是哪一档。基准只在换档时推进 —— 同档每 5s 刷一次，拿上次渲染当基准箭头会一直抖，那是噪声不是趋势 |

**一处偏离原计划的地方**：完成判据原写"Top 10 与**明细表**逐行对得上"。
核实后做不到 —— `/inner/sw/trace-slow` 的 SQL 是 `WHERE endpoint = ?`（**单 endpoint 精确匹配**），
按耗时降序、受 `limit` 截断，它**只答得出一个端点的慢段**，答不出跨端点的排名。
硬要"逐行对得上"就得让榜建立在"最近 N 条慢段样本"上，那得到的是**样本里的排名**，
拿去谈资源申请是不成立的证据（量级会被 limit 截断掩盖）。

所以改成：榜建立在**全量调用的真聚合**上（落 H2、跨重启保留），每行给一个「慢调用 ›」入口
—— 按**该端点自己的 P95** 作阈值跳慢查询页看逐条慢段（traceId 可点进链路图）。
**榜给量级与名次，慢查询页给证据，两边数字不相加、不并排混读**，页内已写明。

**完成判据核对**：排序 / 同分兜底 / 名次四态 / 「基准只在换档推进」（含 W1→W2→W1 序列）
均已用真实形状的聚合行跑过断言，全通过。回归测试固化在
`verify/frontend/slow-topn-render.test.js`（38 条，纯 Node，把页面逻辑原样切出来跑）。

**过程中抓到的两个真问题**：

1. `topnDelta(null, …)` 把"没有基准"当成"新进榜"，**首屏会给每个端点都贴一个"新"字**。
   "无基准"与"上一档里没这个端点"必须分开。
2. 榜的行模板里用了已被删除的 `rank` 变量 → 首屏抛 `rank is not defined`。
   它在渲染链里排在主表**之前**，一抛错整条 `.then()` 断掉，**KPI 与所有表格一起空白**。
   `node --check` 查不出这类**运行时** ReferenceError，纯逻辑断言也不碰模板字符串 ——
   所以补了"真正调用渲染函数"的冒烟测试（同上文件）。

**顺带抽出 `dashboards/range.js`**：两页查同一批分钟桶的公式原先要抄两份，漂了没人查得出来。
现为共享实现（`SWRanges.buckets()`），指标大屏与本页同源，测试里断言了它的档位与分辨率边界。

### #3 慢调用 TopN 榜（原计划存档）

**价值**：争取资源最硬的证据 —— *"哪个端点慢、慢到什么量级"*。原来是明细表，看不出排名。

**成本**：小（数据已在 `/inner/sw/trace-slow` 与指标读口里），只做排序 + 版式 + 前 N。

**完成判据**：Top 10 与明细表逐行对得上；同一端点在不同时间窗的排名变化能被看出来。

## ❌ 明确不做（对本仓定位得不偿失）

| SkyWalking 的功能 | 不做的理由 |
| --- | --- |
| eBPF Profiling / Kernel Profiling | 要 eBPF 与特权的 agent，与"OAP-less 单体"定位正交；演示性弱、解释成本高 |
| Service Mesh 拓扑 | 本仓不是网格，拓扑会退化成单节点 —— 正是我们刚在页面上消灭掉的那个形态 |
| Browser Monitoring | demo 没有前端埋点诉求；为一个不存在的场景引入采集链路 |
| 日志全文检索（Log 集成） | 插件已有应用日志数据流但没有检索场景；为它引入存储与索引，ROI 差 |
| Event 分析（OOM / GC 事件流） | 偏 JVM 调优，对外汇报无感；本仓已有 JVM 面板 |
| 火焰图（Pyroscope / profiling trace） | 需额外部署 + 采样配置，改动面大、收益窄 |
| BanyanDB / 存储层换型 | 与"单体内、内存优先"的决策相反（见 ADR-03 / ADR-04） |
| OTel 上报链路 | **已经支持**（无侵入接入），不必再自建一套 |
