## 1. 先弄懂：P95 / P99 是什么

想象每分钟给"请求耗时"拍一张快照：

- **P50（中位数）** = 一半请求比它快、一半比它慢。
- **P95** = 95% 的请求比它快，**最慢的那 5% 有多慢**。
- **P99** = **最慢的那 1% 有多慢**（最能暴露"卡一下"的尖峰）。

大屏想告诉你："这段时间系统体验如何。" 于是它要把很多分钟的数据**汇总成一段时间**（比如近 24 小时）。  
**问题就出在"汇总"这一步。**

---

## 2. 一个生活比喻（记住这一个就够）

把每分钟想成"一天里某一个小时的高速路况"，P99 就是"最堵那 1% 车花了多久"。

- **把每小时的 P99 平均一下** → 好像也能看，但"某一小时突然大堵车"会被别的正常小时**平均掉**，尖峰消失了。  
  → **这正是现在 `metrics.html` 大屏在干的事（加权平均）。**
- **直接挑"最堵的那一小时"的 P99** → 不会被抹平，一眼看到最坏情况。  
  → **这正是这次新页面干的事（最差分钟）。** 但它可能被"数据很少的一小时"带偏（见下）。
- **把全天所有车的数据合在一起重新算 P99** → 最准，但需要**改数据存储方式**，本次**没做**。

一句话：**多个 P99 不能简单平均**。数学上"平均 P99" ≠ "整体 P99"。

---

## 3. 那"5000 采样"是不是罪魁祸首？——不是

监控为了省内存，每分钟最多只留 **5000 条**耗时样本。你可能会想：请求有 7000 条，只留 5000 条，那 P99 岂不是"失真"了？

**不是。** 理由：

- 它是**等概率随机抽样**（不是只取前 5000 条）：每条请求被留下的机会一样，所以样本能代表全体。
- 7000 里留 5000 ≈ **71%**，非常多，算出来的 P50/P99 是**接近真实值的"约等于"**，不是"错"。
- 而且 **请求数、错误数、平均耗时、最大耗时是完全精确的**（每个请求都算了，不走抽样）。只有 4 个分位数是"约等于"。
- 大屏上 `样本 5000` 只表示"采样池满了"；`sampleOverflow` 只表示"超出的数量有多少"——**都不代表分位算错**。

**真正的锅在"跨分钟合并平均"，不在 5000。**

**不过有两个最容易踩的点，务必分清：**

1. **"5000"是"单个接口、每分钟"各一份，不是全站总量。**  
   折算下来：**单个接口的 QPS < 83.3**（5000 ÷ 60）才不会触顶。
   - 总 QPS 84、分散在 20 个接口 → 每个才 ~4/分钟，**不会**触发；
   - 总 QPS 84、全打一个接口 → **会**触发。
   - 所以该问的是"**最热的那个接口**，一分钟多少请求"，而不是"系统总 QPS 多少"。
2. **就算触发了，也只是"约等于"，不用太担心**；而**真正要担心的"合并平均"问题，和 QPS 完全无关**——哪怕 QPS = 1，只要你看的是"一段时间汇总"，它照样把尖峰抹平。
   - 结论：**"QPS < 84" ≠ "问题不存在"**，只代表"5000 采样这条线不会触发"。

> 自己怎么核实：把 `/inner/sw/metrics` 返回的 `buckets[]` 按 `requestCount` 降序，**第一条**就是当前最热接口的单分钟请求数（和 5000 比）；再看计数器 `sampleOverflow`（>0 = 有接口触顶）、`endpointOverflow`（>0 = 接口数打满 500）。

## 4. 现在到底哪些数能信、哪些要打问号

| 你看到的                                    | 可信吗                  | 说明                       |
| --------------------------------------- | -------------------- | ------------------------ |
| 请求数 / 错误数 / 慢数 / 错误率                    | ✅ 精确                 | 每个请求都统计，不抽样              |
| 平均耗时 / 最大耗时                             | ✅ 精确                 | 同上                       |
| **单看某一分钟**的 P50/P95/P99                 | ✅ 基本可信               | 等概率抽样，样本占绝大多数            |
| **一段时间汇总**的 P95/P99（大屏的表格、小时线）          | ⚠️ 约等于，会抹平尖峰         | 是把每分钟的分位"加权平均"出来的，不是重算   |
| 新页面（`metrics-troubleshoot.html`）的「最差分钟」 | ⚠️ 看最坏，但要配"桶数/中位"一起看 | 挑最大，能看到尖峰；断流/数据极少的分钟会放大它 |

**结论：不是数据全坏了，而是"汇总分位数"这件事本身会骗人。**
