logfile-reporter-plugin 能力导览

一个 SkyWalking Java Agent 的本地内存报告插件:把 agent 采集的监控数据从"发往 OAP"改写为"存进应用进程内",无 OAP 后端也能自查全链路与指标。
本页是演示应用 demo-app 的入口——下面告诉你插件是什么、名字从哪来、怎么跑。

插件是什么

默认情况下,SkyWalking agent 通过 gRPC 把监控数据上报给 OAP(Observability Analysis Platform)后端。本插件拦截并改写这条通路:数据不再外发,而是写入应用进程内的有界缓存,通过宿主工具类暴露的 JSON 接口实时可查,并支持不重启的运行时开关。

OAP 模式(默认)

agent 采集 → gRPC 上报 → OAP 聚合存储 → SkyWalking UI 可视化。生产级全链路,但需要独立部署后端。

本地内存报告(本插件)

agent 采集 → 进程内有界缓存 → 应用自带 JSON 接口自读(统计接口 + 自建仪表盘)。OAP-less:gRPC 通道禁用,单应用自足,适合开发调试、离线自查与能力演示。

插件接管并缓存的六类 agent→OAP 数据流,每类都有独立统计读口,多数配有仪表盘:

链路段 trace segment

GET /statistic
同一 traceId 的多 segment 合并缓存,span 时间线可查。
查看仪表盘 →

JVM 指标

GET /statisticJVM
CPU / 堆内存 / 线程 / GC 等 JVM 运行时指标。
查看仪表盘 →

meter 指标

GET /statisticMeter
micrometer 桥接的自定义单值与直方图指标。
查看仪表盘 →

应用日志

GET /statisticLogs
agent 采集的应用日志条目,本地可回看(读口无独立仪表盘)。

心跳 / 实例属性

GET /statisticInstanceProperties
实例心跳与应用/OS/环境属性键值对。
查看仪表盘 →

profile 快照

POST /profile
线程采样触发与带方法栈的快照列表。
查看仪表盘 →

另有两项附加能力:Trace 告警——基于已合并链路的慢/错识别规则,命中后经 HTTP webhook 通知外部(默认关闭);运行时开关——不重启即可启用/禁用数据流写入缓存,便于对比验证。

"logfile" 命名来历

名字有误导性——它不读取日志文件。最初设想是把监控数据写入日志文件,实现中受 Alibaba Druid 内存缓存思路启发,改为进程内内存存储,名字沿用至今。

怎么跑

前置:JDK 8、Maven。agent 与插件环境用 setup 一步备齐(检测/下载 agent 9.4.0、安装插件、产出启动命令):

pwsh> pwsh ./scripts/setup.ps1

然后一条命令完成 构建插件 → 安装进 agent → 启动 → 造数 → 断言 → 报告:

pwsh> pwsh ./scripts/validate.ps1

想边跑边看实时数据,用手动模式(保持运行后刷新本页与仪表盘):

pwsh> pwsh ./scripts/run-with-agent.ps1 -SkipPluginBuild

仪表盘导航页:/dashboards/index.html(汇总全部六个数据流仪表盘)。

验证入口:scripts/validate.ps1(一键验证回路)·scripts/run-with-agent.ps1(IDE/手动调试)· 术语指引见仓库根 CONTEXT.md
