H2 影子对账 · 使用说明

这份是给人看的操作指南——不要求你懂 SkyWalking 内部结构。跟着三步走,你能亲眼看到"插件把链路数据同时写了一份到本地 H2,并和原来的数据逐条核对一致"。

① 看对账仪表盘 ② 打开 H2 控制台 返回首页

一句话解释:这是个啥

插件本来把链路数据放在应用进程的内存里(重启就没)。现在它额外再写一份到本地 H2 内存数据库(就是常说的"影子数据"),然后每隔几秒拿两边逐条对账,确认新写法没把数据搞丢或搞错。

对账结果有两个地方能看:对账仪表盘(给应用界面看)和 H2 Web Console(像数据库客户端一样直接查 SQL)。两者数据同源,可以互相对照。

"H2 内存模式"= 不落盘、不产生磁盘文件,关掉进程即消失。所以它试运行零成本、可随时回退;适合测试环境观察,不是生产存储。

三步上手

1

用"带 H2 控制台"的方式启动应用

在仓库 agent/demo-app 目录下执行(它会构建、启动、造数、跑断言,然后保持运行):

PowerShell
pwsh ./scripts/validate-h2.ps1 -ConsoleEnabled -KeepRunning -SkipPluginBuild -SkipAppBuild

看到类似 H2 验证全绿 (exit 0) 和 保持运行中(PID=...) 就成了——别关这个窗口。

若还没构建过插件/应用,去掉 -SkipPluginBuild -SkipAppBuild 让它自动构建。首次可能多花几分钟。
2

看对账仪表盘

浏览器打开:http://127.0.0.1:9600/dashboards/dashboard.html?p=parity

最下面一排数字就是结论:重点是累计差异 = 0。

3

打开 H2 控制台,直接查 SQL

浏览器打开:http://127.0.0.1:8092

登录信息按下面那张表填,点 Connect 就能查"影子数据"。

H2 控制台登录:每个框填什么

打开 http://127.0.0.1:8092 后会看到 H2 的登录页,照抄下表即可:

Driver Classorg.h2.Driver (一般默认就是它,不用改)
JDBC URLjdbc:h2:mem:sw_trace_segment;DB_CLOSE_DELAY=-1
这就是插件影子库的地址;DB_CLOSE_DELAY=-1 表示"连接断了也别把内存库清掉"。
User Namesa
Password留空(什么都不填)
保持默认的 "Generic H2 (Embedded)" 连接方式即可。因为控制台就跑在应用自己的 JVM 里,能直接连到这个内存库。

连上后左边会出现 TRACE_SEGMENT(影子链路数据)和 TRACE_PARITY_AUDIT(对账差异记录)两张表。

常用 SQL(复制就能跑)

把下面任一段粘到控制台上方的大输入框,点 Run:

1. 一共存了多少行(影子数据有没有在写)
SELECT COUNT(*) AS 总行数 FROM trace_segment;
2. 有多少条 trace(和仪表盘的"H2 trace 数"应对得上)
SELECT COUNT(DISTINCT trace_id) AS trace数 FROM trace_segment;
3. 最近 20 条明细(看真实链路行)
SELECT id, trace_id, segment_id, service, endpoint, start_time, latency, is_error
FROM trace_segment
ORDER BY id DESC
LIMIT 20;
4. 按 trace 聚合(每条 trace 有几个 segment)
SELECT trace_id, COUNT(*) AS segment数, MIN(start_time) AS 开始, MAX(start_time) AS 结束
FROM trace_segment
GROUP BY trace_id
ORDER BY 结束 DESC
LIMIT 20;
5. 查某一条 trace 的完整内容(把引号里的值换成真实 traceId)
SELECT * FROM trace_segment WHERE trace_id = '把这里换成 /statistic 里看到的 traceId';
6. 对账差异记录(一切正常时应为空)
SELECT * FROM trace_parity_audit ORDER BY id DESC;

看懂仪表盘上的 7 个数字

H2 影子存储影子功能有没有开。显示"开启"才对。
debug 比对有没有在跑对账。要看到"开启"。
已检查 trace累计对账过多少条 trace,应随时间增长。
累计差异最关键:两边数据不一致的条数。0 就是最好;不是 0 就在下面差异表看具体哪条、差在哪。
H2 trace 数影子库里的 trace 数,应等于控制台里 SQL 2 的结果。
H2 错误数影子写入过程报错次数。健康时是 0。
审计表水位差异明细表的行数 / 上限(1000)。零差异时是 0 / 1000。

下方"最近对账差异"表:零差异时显示"暂无差异记录";一旦有差异,会逐条列出检查时间、traceId、差异类型、期望值、实际值和说明。

常见问题

打开 8092 是空白 / 网页一直转圈?

说明控制台没起来。确认启动参数带了 -Dskywalking.plugin.logfilereporter.h2.console_enabled=true,并在启动日志里搜到 Web Console started on port 8092。若端口被占,用 -ConsolePort 8093 换一个。

以前打开是空白,还看到 "Message 90061 not found"?

那是旧版本的已知问题(H2 的网页资源在打包重定位后丢了),已经修复。用重新构建过的插件 jar 重启应用即可。

连上后表是空的?

说明还没有流量经过应用。随便触发几个请求再刷新:

curl.exe --noproxy "*" http://127.0.0.1:9600/api/trace-alert-demo/self-call
curl.exe --noproxy "*" "http://127.0.0.1:9600/api/trace-alert-demo/slow?ms=4000"
curl.exe --noproxy "*" http://127.0.0.1:9600/api/trace-alert-demo/error

对账每 5 秒一轮,等 6 秒再刷新看。

提示 "Database may be already in use"?

同一台机器上开了多个应用实例,抢同一个内存库名字。只保留一个实例即可。

对账差异不是 0,要紧吗?

看差异类型:统计/排序口径不同可能造成"看起来不一样";先看仪表盘差异表的"说明"列,或到仓库工单 .scratch/h2-trace-storage/issues/07 记录结论。正常情况下造数流量应为 0。

能从别的机器访问控制台吗?

可以,控制台已允许远程访问:用 http://<部署机IP>:8092。但请注意下面的安全提醒。

安全提醒

H2 控制台能对这个库执行任意 SQL(包括改数据、删表)。请只在测试环境开启、用完即关,不要在生产长期打开。默认就是关闭的。
