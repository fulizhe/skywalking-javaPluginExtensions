口径说明（看这张榜之前必读）

  • 榜排的是窗口内「全量调用」的分位，不是「慢调用次数」。数据源 /inner/sw/metrics/query?aggregate=true（真聚合、落 H2、跨重启保留）。
  • 「最差 P95」= 窗口内最差那个桶的 P95，不是平均。平均值会把尖峰抹平， 而汇报要问的正是"最坏的时候有多坏"。
  • 分位是按请求数加权平均的近似值（≤24h 用分钟分位，7d/30d 用小时分位， 小时分位本身是分钟分位的加权近似）；样本不足的桶分位为空、不参与加权。
  • 「慢率 / 错误率」是插件自己的计数口径，与"慢调用"告警的阈值规则是两套判断， 两者不必一致。
  • 点行打开的是「逐条证据」，不是同一份数据：/inner/sw/trace-slow 的 SQL 是 WHERE endpoint = ?（单 endpoint 精确匹配）、按耗时降序、受 limit 截断， 载荷可能已过期。两页数字不要相加。
  • 时间窗的桶范围与指标大屏同源（共用 range.js 的 SWRanges）—— 同一档位在两页查到的是同一批分钟桶。24h 及以内走分钟分位，更长走小时 rollup。
  • 时间窗拉到 7d/30d 时，被清理掉的旧桶会让早期的名次失去样本； 那时看「名次变化」要结合 bucketCount 一起看。
