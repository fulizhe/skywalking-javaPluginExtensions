口径说明（读这张图前必读）

  • 总览 / 自启动以来都是 self 居中的星图：边宽 ∝ 调用量、边色 = 边级错误率、 光点沿边流动 = 调用方向（self → 依赖）。总览是窗口聚合（self 到每个组件一条边）， 自启动以来是进程累计（累计表不存耗时样本，故不显示 p95，只给累计最大耗时）。
  • 依赖边只统计同一个链路段内的调用（段内 Entry × Exit 配对）。
  • 异步调用的出口依赖不进图——跨段配对需要父段索引，而父段可能已被淘汰， 那会产生无法与「没有这个调用」区分的随机缺边。@Async 出口请到链路可视化页看。
  • 依赖节点只到组件类型，不区分具体实例地址（同一组件的多个实例会并成一个节点； 同理，访问 3 个不同站点的 HTTP 也只是 1 个 Http 节点，不是 3 个依赖）。
  • 总览档中心只有一个「本服务」节点，它是窗口内全部入口端点的聚合 （合计调用 / 合计错误 / 覆盖端点数），端点维度在明细档与本页边列表里看。
  • 「清单」档不看时间窗，恒为进程累计（自启动以来，一行一个外部依赖）—— 它回答的是"这个进程伸出去过哪些手"，用来给资源申请 / 拆单体当论据，与"此刻谁在调谁"是两件事。 该档下关系图会收起、表格占满宽度：不并排展示，免得累计表的数字被当成窗口边的图读。 点列头可排序，点行回到总览档。
  • 明细档的依赖节点标签取该边上去重后的出口操作名（每边最多 8 个，超出会截断并标 +N； 完整列表看节点 tooltip）。总览档只显示组件类型。
  • 节点颜色与标记的判据是边级错误率（取自出口 span 的 isError）， 不是规则引擎告警；边上的耗时分位是蓄水池抽样得出的，样本少时尾部分位噪声大。
    反过来也不成立：span 判成功 ≠ 调用真的成功。例如 Kafka 在 broker 不可达时 send() 会等满 max.block.ms 抛超时，而 agent 的 producer span 靠异步 callback 回填错误、同步超时这条路上没有 callback —— 那条边于是 errorCount = 0（耗时却会涨到超时上限，那才是线索）。 判断"这次调用到底成没成"以端点自己的响应/业务日志为准，别只看颜色。
  • 连接都没建起来的依赖，不出现在这张图上 —— 依赖边建立在「调用已发生」之上， 而连接建立本身（connection refused、主机名解析失败）发生在被观测的调用之前， 不会产生依赖边。所以某个组件缺席不能读成「没有这个调用」， 要确认请到链路视图里看那条请求的失败现场。
  • 数据为纯内存、分钟级窗口、重启即失（与 H2 影子层同语义）。
    本页只有两档：「近 5 分钟」看窗口内的边 —— 插件只保留「当前分钟 + 3 个晚到桶」 ≈ 4 分钟，再往前的桶已被淘汰，所以这一档拉不出更长历史； 「自启动以来」读插件侧的进程累计（不参与淘汰），回答"这个进程伸出去过哪些手"， 重启即从零开始。
    要看小时级 / 天级趋势请看指标大屏—— 端点级指标落 H2并做小时 rollup，那一页才有 1h/6h/24h/7d/30d。
