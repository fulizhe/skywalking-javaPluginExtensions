demo-app 数据流仪表盘

logfile-reporter-plugin 六类数据流(链路段 / JVM / meter / 实例属性 / 告警 / profile)的本地内存报告可视化, 外加一项 H2 影子对账调试面(H2 影子写入状态与新内存视图的一致性比对)。 页面轮询与验证回路(scripts/validate.ps1)同一批 JSON 契约,静态资源随应用打包,无外部网络依赖。 09–11 为 链路查询面(双源对照 / 慢查询 / 可视化);页面底部另列 原始 JSON 读口。

01
Trace 缓存统计
链路段按 traceId 合并的缓存表与 span 时间线,含运行时开关状态
02
JVM 指标
CPU / 堆内存 / 线程 折线图,GC、内存池与类加载明细
03
Meter 指标
micrometer 桥接的单值与直方图指标,支持按名称过滤
04
实例属性
心跳携带的应用/OS/环境属性键值表
05
Trace 告警
告警运行指标、规则命中计数与 webhook 收讫事件流
06
Profile 快照
线程采样触发与带方法栈的快照列表
07
H2 影子对账
H2 影子写入状态、对账计数与最近差异明细(与 H2 Web Console 同源)
08
Trace 指标
真实 trace-based metrics:请求/错误率/慢调用与 P50–P99 分位,含 QPS;头部 1h/6h/24h/7d/30d
09
双源对照 · 逐段 diff
同一 traceId:H2(为准) vs 内存热层(参照)并排 + 按 traceSegmentId 对齐(both / span-diff / h2-only / mem-only)
10
慢查询
按 endpoint + 耗时阈值查慢段(latency 降序),点行下钻整条链路
11
链路可视化
按 traceId 展示 span 时间线(通常由上面两页点行进入,带 ?traceid=)
12
指标排障 · 最差分钟
③ 口径:分位=范围内「最差分钟」(各桶取最大),与 metrics 的加权平均并排对比;端点表按最差 P99 排序,可下钻到端点/链路
13
依赖拓扑
self → 外部依赖的二部图:总览档只到组件类型(可截图),明细档带出口操作名;边上有调用量/错误率/耗时分位,点节点下钻慢查询

原始读口（JSON，点击直开）

  • /inner/sw/trace-recent?limit=20 —— 最近链路 header（挑 traceId）
  • /inner/sw/trace-query?traceId=<id> —— H2 取整条链路（为准）
  • /inner/sw/trace-memory?traceId=<id> —— 内存热层取整条链路（参照）
  • /inner/sw/trace-slow?endpoint=&minLatencyMs=&limit= —— 慢查询行列表
  • /inner/sw/trace-parity —— 影子对账 / 孤段 / H2 状态
  • /inner/sw/metrics —— 指标实时快照（含 QPS）
  • /inner/sw/metrics/query?endpoint=*&limit=20 —— 指标条件查询（加 &aggregate=true 出每端点一行）
  • /inner/sw/metrics/extremes —— 每端点最大耗时那次的 traceId
  • /inner/sw/topology —— 依赖边（entry × 组件），加 &view=summary 出总览档
运行方式:pwsh ./scripts/validate.ps1(一键验证)或 pwsh ./scripts/run-with-agent.ps1(手动模式,保持运行后浏览器打开本页)
