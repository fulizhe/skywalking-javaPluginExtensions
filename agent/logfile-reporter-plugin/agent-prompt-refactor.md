# Code Review 与重构流程

对指定源码文件执行 code review，输出分步骤优化建议并落地实现。被 review 的文件与产物路径由指令给出。

## 流程

1. **Review 指定文件**，给出分步骤优化建议。产物写入同目录下 `xxx-refactor.md`（`xxx` 为被 review 文件去掉 `.java` 的类名）。完成标准：产物文件已创建，且每一条改进项都写明「问题 → 源码位置 → 修复方案」。
2. **标注每项状态**。每个改进项后直接标注 `**状态**：✅ 已完成 / ⏳ 待做 / 💡 有更优方案`，不单独设进度小节，避免信息不同步。完成标准：产物里**每一条**改进项都有状态行。格式参考 `LogFileTraceSegmentServiceClient-20260218.md`。
3. **按优先级落地**。全盘考虑后，先完成指令指定的步骤 X，其余保持待做。完成标准：指定的改进项已实现并自检通过。

## 代码规范

- 字段用 `final` 修饰；仅当后续确实需要重新赋值时才去掉。
- 每个改动处保留类/字段注释，说明设计意图与线程安全约定。
